# Publy workbench (development)

Shared browser/Glaze frontend following `design/prototype/preview-article.html`. From the root after `pnpm install --frozen-lockfile`, run `node scripts/build-workbench.mjs`, then serve `packages/workbench/dist` over local HTTP. Local Markdown, built-in themes, explicitly selected raster images and experimental rich clipboard are implemented. Clipboard requires a secure context and browser support; warnings block copying. Raw HTML, math, WeChat paste fidelity, draft delivery and native WebView runtime acceptance remain open. Source and selected images stay in memory; no account or network publishing in this slice. Not linked from the public site.

Hosted publishing preparation: `prepare-article.mjs` converts reviewed inline HTML and selected raster data into the existing attachment wire format, and `hosted-client.mjs` implements account query, explicit-submit and readback with injected transport tests. Neither module is wired into the UI yet. Cross-origin policy, deployment, secure desktop transport, browser bundling of the preparation entry point and real-draft acceptance are still required.

The development dialog now connects the hosted account query, immutable request preparation, explicit confirmation and read-only result reconciliation. Unknown results lock further submission in the dialog. Credentials and request state are in memory; closing/reloading the page loses them. Production CORS and actual draft delivery remain unverified, and the workbench is not publicly linked.
