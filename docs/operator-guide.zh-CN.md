# Publy 自托管运营者指南

[English](operator-guide.md) · **简体中文**

这份指南写给自己管理 Publy 服务的人。后台管理的是服务，**不是笔记库**：原始文章仍在 Obsidian、Typora 或文件管理器中编辑和整理；公众号草稿则在对应的微信公众号后台查看与公开发布。

目前后台仍是**开发期工具**，公开托管注册和付款尚未开放。旧版用户套餐和订单页面不能证明 Commerce/Permit 授权或真实销售已经生效。

支付宝 Vibe Pay 是计划中的收款方式。沙箱中已验证模拟付款和支付宝签名查单；支付回调、退款、客户权益和正式商户资格仍待验收。现在不要用后台的历史订单记录开通付费服务。技术方案和当前边界见[支付宝接入计划](alipay-vibe-pay-plan.md)。

## 如何进入后台

1. 在自己管理的机器上启动已配置的 Publy 服务。新版开发配置默认只监听 `127.0.0.1`；部署说明见[服务配置](guide.zh-CN.md)和[运维说明](operations.md)。
2. 如果就在服务器本机操作，访问 `http://127.0.0.1:8081/admin`（端口以实际配置为准）。如果服务器在远端，可以在自己的电脑上建立私有 SSH 隧道，例如：

   ```sh
   ssh -N -L 127.0.0.1:18081:127.0.0.1:8081 USER@SERVER
   ```

   将 `USER`、`SERVER` 和端口替换成自己的实际值，保持终端窗口打开，再在本机浏览器访问 `http://127.0.0.1:18081/admin`。也可以在可信网络中使用配置正确、受保护的 HTTPS 反向代理。
3. 输入服务器配置里的 `apiKey`。后台把它保存在当前浏览器标签页的会话存储中，并通过请求头发送。用完请退出；不要把密钥贴到 issue、URL 或聊天里。服务器配置还可能包含公众号 AppSecret，不要整份分享。

新的生产服务模板读取 `/etc/publy/server.json`；旧的自托管服务可能使用 `~/.publy/server.json` 或其他路径。需要在可信的服务器终端**只显示管理员 key** 时，可将下面路径换成实际配置路径后运行：

```sh
sudo python3 -c 'import json; print(json.load(open("/etc/publy/server.json"))["apiKey"])'
```

不要在他人能够看到屏幕或终端记录的地方运行。退出后台只会清除当前标签页保存的 key，**不会撤销该 key**。如果 key 泄露，应按受控流程修改服务器配置、重启服务并更新可信客户端。操作前先备份；不要随意更改或遗失 `secretKey`，它用于解密数据库里的公众号密钥。

## 各个页面管什么

- **概览**：查看服务计数与常用入口。旧版套餐和订单数字只是本地历史记录，不是权威的商业结算数据。
- **草稿任务**：查看服务端排程任务及最近投递事件。等待投递的任务可以在确认后取消；如果取消结果未确认，请刷新状态核对。开始投递后不能在此取消。“草稿已确认”表示微信确认创建草稿，不等于文章已公开发布。历史记录有数量和保留限制。
- **用户**：管理本地用户、key 和旧版套餐字段。这里的开通或延期是运营者修改本地记录，并不代表完成付款或获得 Permit 授权。
- **订单**：历史或隔离测试记录。本地状态和手工操作不能作为真实付款或当前客户权益的证明。
- **账号**：查看配置文件和数据库中的公众号账号。保护好服务器配置与备份；配置文件里的 AppSecret 以明文保存，数据库账号是否加密取决于 `secretKey`。
- **动态**：实时事件需要单独配置 WebSocket 网关。列表为空或未连接，不代表一定没有事件。

## 投递结果不确定时

超时或连接中断不等于草稿失败。保留原请求身份，在可用时运行 `publy publish-result <requestId> --json`，并到正确的公众号草稿箱核对。不要自动重发。当前后台尚不能解决所有即时投递的未知结果；旧备份也可能缺少备份之后的投递记录。重启或恢复之前请先看[恢复与备份说明](operations.md)。

## 日常维护

- 停止所有写入进程后，将实际数据目录与服务器配置一起备份到加密、受限的存储；在隔离环境验证可恢复后再依赖备份。
- 已用少量合成数据演练加密、恢复密钥和恢复任务隔离；这不代表自动备份、独立密钥保管或备份之后的活动恢复已经完成。剩余工作见[恢复操作说明](operations.md)。
- 管理员 key、AppSecret、草稿数据和日志都应保密，不要放到公开反馈中。
- 源码提供的服务模板默认只监听本机；要开放服务，仍需配置身份验证、HTTPS 和网络访问控制。托管、备份留存、客户删除和商户准入尚需发布验收。

非敏感问题可通过 [GitHub Issues](https://github.com/turlamai/publy/issues) 反馈，并使用合成内容说明版本与复现步骤。
