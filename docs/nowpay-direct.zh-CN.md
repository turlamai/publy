# 可选即刻收直连托管月包

[English](nowpay-direct.md) · [收费方案](../PRICING.zh-CN.md) · [服务器安装](../deploy/README.zh-CN.md)

本模式遵循 `2026-10-auth-1`，仅接入 Personal：29元、一个日历月、主动购买、不自动续费。CLI、本地渲染、Obsidian 插件和自托管继续遵循原有免费条款。安装接入代码不表示公开开卖。

## 部署与信任

服务器使用正式版本安装包，签发基线为 Commerce 0.1.2 / Permit 0.2.1，独立安装运行时，不链接开发源码、不借用 Pitboard 包环境。固定系统账户 `commerce-issuer` 独占支付私钥、Permit 签发密钥、0700 状态目录及权益数据库。Publy 只能访问安装包提供的 0660 本地套接字和公开验签信任，不能读这些私钥或写签发库。切换前一致备份并验证两个数据库可恢复。不能将仍接受客户请求的直连服务回退至不支持直连的旧版：旧版会忽略新配置。此类回退必须先停止客户准入，恢复已核验的启用前配置及状态，不能只改版本链接。

在受保护的 `server.json` 配置 `hostedDirect`，完整字段见英文页的 JSON 示例：`socketPath`、`serviceId`、`outProductId`、`issuer`、`racketExecutable`、`verifierScript`、`trustStore`、`purchasingEnabled`。路径须为绝对路径，后面三个文件必须存在。不得同时启用基础网页支付的 checkout/admission 或合成测试通道。真实商品标识与部署记录不进 Git。

两端购买开关默认关闭。正式验签的商品查询须显示 ENABLED、唯一29元 MONTH 档位，核清收款限制并满足当前备案/应用门禁后，才可开放购买。签发端的 `purchase_buyer_allowlist` 可将验收购买入口限制到指定应用账户。停止新增购买不影响核验已有 ALLOW 权益。

所有非管理员托管请求（包括原免费账户）都须重新查询。签发服务自己调用支付宝后产生绑定当前随机请求的 Permit；Publy 独立验证签名、账户、商品、服务、单调修订、平台周期及新鲜度，排队任务执行前再次检查。缓存的付费标志、浏览器返回均不能开通。平台时间从上海时区转换 UTC，区间含起点、不含终点，不把一个月写成30天。

## 购买与恢复

打开 `/hosted`。首次开户填写联系方式，付款前生成 API Key，请保存在密码管理器。已有账户填原 Key 恢复相同账户，不能仅凭联系方式领回 Key。凭据放在认证请求头及 HttpOnly 会话中，不放进 URL；网页仅在当前浏览器会话保留 Key，关闭浏览器或换设备后须输入保存的 Key。遗失时仍走运营者核实身份、轮换凭据的恢复路径。

`POST /v1/hosted/session` 用客户 Key 恢复网页会话；`POST /v1/hosted/status` 查询当前权益。有效权益返回准确有效期、不返回购买入口；需要购买时，只有两端开关允许才展示官方链接及本地生成的二维码。支付宝二维码字段可能是网页地址，不能直接作为图片嵌入。拒绝或查询失败时不授权。付款后可刷新，网页也在有限时间内轮询；服务重启后用同一 Key 恢复。另一设备付款后回原购买浏览器，或恢复相同账户。

返回页独立重新查权益，不接受 URL 中的支付成功标志。本模式无年付、Studio、有效期内续购或时长叠加。到期后须由最新查询要求购买，用户再主动确认下一次购买。

## 额度与失败恢复

每个平台已付周期包含1个公众号、30个成功草稿任务及1 GB活跃解码附件。即时请求认领与额度预留在一个 SQLite 事务完成；排队时预留、执行前再核验。已确认操作身份跨缓存期限和账期仍不能重复投递。明确的投递前失败或平台拒绝释放预留，结果未知则同时保留请求身份及额度，不能超时后自动重发。退款不通过删除其他周期权益来模拟，以平台当前访问决策为准。

成功只计一次；排队、发送中及结果未知均占预留，附件活跃期间计存储，不自动超额扣费。即时未知结果沿用管理员独立查询微信草稿箱的核对入口，并原子结算对应预留。排程未知结果保持阻断，不删除额度记录或强制重发以伪造验收通过。

## 验收边界

合成测试覆盖账户绑定、独立验签、错随机数/服务/商品/主体拒绝、重启恢复、关闭购买、当前拒绝、去重及原子额度耗尽，不代表真实直连支付或退款通过。开卖前还需记录正式商品查询、用户亲自确认付款后的准确有效期、重启恢复、到期与再次购买、官方支持的退款撤权。原基础网页支付沙箱证据不能代替这些验收。内容保留/导出、商户限额、备案和真实微信投递仍按既有上线任务核验，不从库 CI 推断完成。
