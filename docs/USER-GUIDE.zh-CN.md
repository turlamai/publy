# Publy 使用指南

[English](USER-GUIDE.md) · **简体中文**

将 Markdown 转为微信公众号文章草稿与图片卡片，提供本地预览和自托管投递服务。

## 当前可用状态

CLI、默认主题、Obsidian 和自托管按现行许可证保持免费。公开托管订阅尚未开放，不销售无限量套餐。

开发版插件已将渲染资源嵌入 `main.js`。离线三文件安装仍在测试；真实干净笔记库的安装与更新验收尚未完成（[#12](https://github.com/turlamai/publy/issues/12)、[#15](https://github.com/turlamai/publy/issues/15)）。

## 平台与安装

目前可使用开发版 CLI 或 Obsidian 插件。当前发布附件包含 Obsidian 插件。服务端需要稳定出口 IP，以及公众号实际具备的官方 API 权限。开发版服务默认只监听本机；需要远程访问时请配置经过保护的 HTTPS 反向代理。旧版若直接对外监听，升级时需调整访问方式或明确设置 `host`。

源码构建需要 Node.js 22+、pnpm 和 Git；步骤见[开发版安装与配置](guide.zh-CN.md#准备工作)。发布附件不等于完整部署服务。

## 从 Typora 或 Obsidian 使用

Typora 可直接把 `.md` 原文件交给 Publy；Obsidian 可以使用已有插件
或原始 Markdown，不需要复制整个笔记库。不再开发其他编辑器专用适配。当前开发版可以运行
`publy check "D:/Notes/article.md" --json` 做**离线**图片、封面和卡片结构
预检查，再运行 `publy preview` 预览；这两项都不会投递草稿。
支持 Typora 的本地 `typora-root-url` 和嵌套图片目录，缺图会明确报告，
也不会改动原文件。**但普通用户的一键安装包尚未通过验收。**

· [English](editor-workflows.md)

开发版插件的「复制排版内容」遇到缺失、渲染失败或仍需本地附件的图片和公式时，会停止复制并保留原剪贴板。含附件的内容可使用草稿投递流程。

## 使用独立文章主题（CLI 开发版）

内置主题可以离线使用。要使用来自可信来源的纯内容主题包，运行 `publy theme add ./theme.json`，再用 `publy theme preview 主题ID` 预览，并在渲染时指定 `--theme 主题ID`。`publy theme ls` 会列出已安装的文章主题；替换时运行 `publy theme update ./new-theme.json`，删除时运行 `publy theme remove 主题ID`。如需回退，请保留旧主题包，先移除当前版本再添加旧文件。同一系统用户运行的 Obsidian 可以选择通过校验的已安装文章主题：安装后重新打开插件设置或预览面板即可。CLI 管理本机共享主题包，插件本身不会下载主题。

通过 HTTPS 获取主题包时，先从可信渠道单独核实完整文件的 SHA-256，再运行 `publy theme add https://example.com/theme.json --sha256 校验值`。摘要只能核对下载内容与该值是否一致，不能证明作者身份；下载不跟随重定向。主题包是纯内容 JSON，不是可执行软件包，只接受限定在 `#publy` 下的一小部分文章 CSS；远程资源、CSS 导入、脚本与 CSS 转义会被拒绝。目前没有签名主题广场或自动更新功能。

要将自己的 CSS 制作为主题包，可先保存类似 `#publy p { color: #123456; }` 的样式文件，再运行：

```sh
publy theme pack my.css --id my-style --theme-version 1.0.0 --name "我的主题" --license MIT --output my-style.json
```

命令会校验内容、拒绝覆盖已有输出，并打印主题包的 SHA-256。分享主题时请附上合适的许可证；原 CSS 和 Markdown 文件不会被修改。主题保存在 `~/.publy/themes`，请自行备份需要保留的主题包。

迁移旧的本地主题时，请先备份它的 CSS 和许可证，再对副本运行 `theme pack`。不受支持的选择器或声明需要你明确调整；Publy 会拒绝，而不会悄悄降低校验要求。你本人信任的 CSS 文件仍可通过 `--custom-theme /path/to/theme.css` 临时用于一次渲染；这是旧的可信输入路径，不具备主题包的安全边界。不要运行旧包的安装脚本；主题包流程不会自动导入 npm 包。

## 我的笔记和草稿在哪里？

Publy 不建立笔记库，也没有用来浏览或编辑笔记的后台。你仍然在
Typora、Obsidian 或文件管理器中查找、编辑、整理和备份原始 Markdown
及图片；Publy 读取你选择的文件进行检查和排版，不会替你迁移笔记。

草稿投递成功后，请登录**微信公众号平台**，在对应公众号的草稿箱中
查看、编辑和管理草稿。Publy 不会替你公开发布。若结果显示未知，先在
微信草稿箱核对，再决定是否重新提交：没有查到服务端记录，并不能证明
微信没有收到草稿。

自托管服务另有供运营者使用的 `/admin` 管理页面，它管理的是服务用户、
公众号账号、排程草稿任务、历史订单和事件，不是笔记管理器。「草稿任务」
可以查看等待、已确认与结果未知的状态，以及最近的投递记录；记录数量
有限且受日志保留影响，不能代替检查微信草稿箱。这个页面目前仍是开发期工具，公开托管和收款尚未开放；请通过 HTTPS 或可信的私有网络访问，
不要把管理员密钥分享给其他人。[运营者指南](operator-guide.zh-CN.md)介绍后台登录和各页面操作，[服务端操作与备份](operations.md)提供更多运维细节。

## 第一次使用

1. 按源码安装说明安装，先在本地预览一篇非敏感 Markdown，再配置投递。
2. 配置自己的服务器与账号，将真实出口 IP 加入白名单，AppSecret 仅放在服务端。访问使用 HTTPS 或私有隧道。
3. 投递一份测试草稿，在微信后台确认结果。草稿投递成功不等于文章已公开发布或群发。

## 数据、备份与恢复

CLI 和插件在读取完公式、SVG 与卡片渲染中间文件后会清理这些文件，不会删除原始图片。供你打开的预览 HTML 是输出文件，可能包含文章内容，请在用完后删除。本地保留 Markdown 与媒体原件。服务配置、数据库、任务历史与加密材料应一起备份到受限、加密存储中；恢复前先停止所有服务并隔离网络；旧备份中的等待任务可能已经投递过，须按[恢复步骤](operations.md#backup-and-restore-developer-self-hosted-deployments)隔离并核对备份之后的草稿和账号变更。

投递连接中断时，结果是「未知」而不是「失败」：先按原请求身份查询（`publy publish-result <key>`，或插件里的「查询结果」），再检查公众号草稿箱。服务端只有收到成功回执才会记录结果；即使请求身份相同，重新提交仍可能创建重复草稿。定时任务中断后也应先核对草稿，不要盲目重试。

## 联网、密钥与隐私

渲染可在本地完成。投递会经你选择的服务器把内容、媒体及账号凭据或派生令牌用于微信官方 API。应检查服务日志、重试历史和存储；不能笼统承诺“正文与密钥绝不落盘”。不要在 URL 或截图中分享 API key。

## 已知限制

公开托管注册、支付、租户隔离、留存删除与可靠任务恢复尚未通过验收（#7、#8）。不要将 AppSecret 发往未公告的托管端点或 issue。

## 升级与停止使用

升级前备份配置与数据，核对源码版本和依赖。先在隔离环境验证，再替换正在使用的版本。停止服务或程序后再清理本机数据；外部平台上的内容与凭据需在相应平台单独管理或撤销。

## 获得帮助

在 [GitHub Issues](https://github.com/turlamai/publy/issues) 反馈，中文或英文均可。提供版本、系统与架构、安装渠道、复现步骤、预期和实际结果。先用合成样本复现；不要附上密钥、授权文件、数据库、原始私密文档或完整日志。公开支持不承诺响应时限。
