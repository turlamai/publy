# Publy 产品范围：Markdown 到微信公众号草稿（更新于 2026-11-05）

[English](platform-strategy.md) · **现行明确决定**

**Markdown 是输入，微信公众号草稿箱是发布目标。** 通用 Markdown 和
Agent 工作流都是一等入口；Typora 与 Obsidian 是可选写作入口，使用 Publy
不要求依赖特定编辑器。

## 完整的用户体验

**在原有文件中写作 → 本地检查图片与排版 → 预览 → 明确选择目标公众号 →
保存到草稿箱 → 查看结果或恢复未知状态。**

- **Markdown 与 Agent：** 直接使用任意编辑器保存的原始 Markdown，或由
  用户明确授权的 Agent 检查、预览并创建草稿；不迁移源文件。
- **Typora：** 直接读取原始 Markdown，正确识别相对图片、当地
  `typora-root-url`、封面和公式；不改动源文件，不强制迁移。
- **Obsidian：** 优先把插件的预览、卡片、公式和官方三文件安装验收做好；
  公众号选择与草稿操作必须明确，不复制整个 Vault。
- **微信公众号：** 唯一实际投递协议。绝不把草稿当成公开群发，
  不通过模拟登录绕过官方权限。把图片正确性、凭据安全、发布结果与
  超时恢复做到可靠。公开托管仍须通过 Commerce/Permit 和实际运营门禁。

普通 `.md` 文件是正式支持的产品输入，通用工作流须独立于编辑器验收。
是否为其他编辑器提供专用集成，取决于明确的用户需求与单独验证。

## 发布范围

当前产品只投递到微信公众号草稿箱。新增发布目标需要单独的产品决定。
用户于 2026-11-05 明确：普通 Markdown 文件或获得明确授权的 Agent
本身就是完整入口。

## 交付优先级

1. **内容准确：** 通用 Markdown 和可选编辑器适配的图片、相对路径、封面、公式、
   卡片和 HTML 安全；缺图不可静默发稿或替换同名图片。
2. **体验出色：** 无服务器本地预览、错误引导、选择目标账号、仅
   草稿投递、确定与未知结果恢复，三系统干净安装、无障碍与交互美观。
3. **真实可靠：** 公众号官方 API、固定出口 IP 与白名单、真实草稿
   验收、密钥管理、备份恢复和重复/超时保护。
4. **可持续收费：** 托管服务、Commerce/Permit 实时权益、
   合理配额、退订退款、错误可追踪、用户支持完成后再对外出售。

**完成 Publy 不以新增平台为验收条件。** 以后除非用户再作出新的明确
产品决定，否则当前路线不再讨论支持其他发布目的地。
本决定不修改现有许可证，也不代表公开托管已经开卖。
